A verdict has three values, not two

PASS is never the fallthrough branch. An occluded lens, a crashed NPU, a dropped serial link, a smudged expiry date and an unparseable model reply all land on INDETERMINATE - and INDETERMINATE never opens anything.

PASS
Every critical item positively found, in date, above the confidence floor
Latch released
FAIL
A positive finding of non-compliance
Latch engaged
INDETERMINATE
Compliance could not be established
Latch engaged

The reference design for this hardware decides with if "missing" in reply or "no" in reply. We kept that logic executable and replay it on every frame against the same verbatim model output. Pick a scene and watch both decide.

Why it needs a vision model

Presence is not serviceability. A sealed, undamaged, correctly-placed packet of expired haemostatic gauze passes every visual check and is still not something to hand a medic. Reading a printed use-by date off crumpled foil and reasoning about whether it has passed is work object detection cannot do and a barcode scanner cannot do.

A kit can be complete, undamaged, every tick green - and still fail. Try the scene.

Voice cannot open the latch

The operator has both hands in a tray and is probably wearing gloves, so voice is the right interface. It is also the one with the shortest path to a catastrophic mistake. No member of the Intent enum releases the latch, so there is no value the resolver can return that a caller could turn into a RELEASE. Override attempts are recognised specifically, so that asking is refused and recorded.

Honest limits

  • It has not yet run on the real hardware. The Snapdragon host and the UNO Q are provided at the event. Every item on the bring-up checklist is a behaviour a test already pins against a simulated implementation, but simulation is not silicon.
  • Counting is the model's weakest axis. Quantity is enforced and a count that was never taken fails closed, but counting small identical objects is harder for a VLM than identifying them.
  • Tamper-evident, not tamper-proof. The audit chain catches editing, deletion and reordering. It does not stop someone with write access who rebuilds every subsequent hash.
  • Single-station. No fleet management, no multi-site aggregation.

Every verdict on this page was produced by the project's own InspectionEngine through the same resolve_verdict the hardware uses. Nothing here is hand-written.
